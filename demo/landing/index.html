How Librarian answers a question

In August a user has tried three Korean restaurants. By late September it’s four. In October they ask. The answer is one sentence in months of chat, next to dozens that look almost right.

  1. It's a fact, a recommendation, a count, an update or a date. Each gets its own search.

  2. Keyword and meaning search over every turn, reranked on our own machine. Reactor only sees the passages we pick.

  3. About three dated passages. Dates and day gaps are computed in code.

  4. It reads 0.2% of the archive and cites the sessions it used.

  5. If the evidence is weak, the answer is “not in memory”.

Who it's for

Any assistant that talks to the same person for months: agents, companions, support desks and teams.

Proactive personal agents

Agents that work for you around the clock: booking, buying, planning. Before they act, they need your preferences and commitments, with proof.

Book dinner for Friday.

The agent checks your diet, your Friday plans and who's coming. Every fact comes with the conversation it was said in. Anything not in memory becomes a question for you.

Companions and coaching personas

Companion apps, coaches, branded characters, game NPCs. The longer the relationship, the worse they remember.

  1. What's my cat called?The fact, with the session it came from.
  2. That book you recommended?Its own past advice.
  3. I moved in July.The latest value wins. Both get cited.
  4. How long since my surgery?Dates computed in code.
  5. Remember our trip to Rome?“I don't think you told me about Rome.” No invented memories.

These are the five question types of the Reactive AI challenge. We score 87.1 on them.

What goes wrong in long chats

Facts change

Three Korean restaurants in August, four in September. The latest wins, and both get cited.

Answers hide in one line

“A kitchen gadget” turns out to be an Instant Pot, mentioned once in passing.

Some answers don't exist

Missed by the first pack→Instant Pot

When the first evidence pack misses, the model gets a private link to the user's archive and runs its own follow-up searches, then answers from what it found, with citations. Any agent with tool access can do this through the MCP server. In our live test, Reactor did not open the link yet.

Tech stack

Python for retrieval, Reactor for answers, Cloudflare for hosting.

Retrieval Python 3.12

  • Question router and 5 type-specific lenses
  • BM25 (bm25s, Snowball stemmer)
  • Dense embeddings: BAAI/bge-small-en-v1.5 (384-d) via sentence-transformers
  • Reciprocal rank fusion (k = 60)
  • Cross-encoder reranker: ms-marco-MiniLM-L-6-v2
  • PyTorch on CPU
  • Dates, day gaps and counts computed in code

Answering

  • Reactor (Reactive AI) over its WebSocket API
  • Evidence passages labelled [E1]…
  • Citations mapped to session ids
  • “Not in memory” when evidence is missing
  • No other hosted LLM anywhere in the pipeline

Ask-back and plugin

  • Private per-question memory links Reactor can open
  • MCP server (JSON-RPC over Streamable HTTP) with 6 tools

Hosting

  • Cloudflare Pages: static site, plus Functions for the API proxy and the MCP server
  • Cloudflare Containers (4 vCPU) running the Python backend behind a Worker
  • KV and a service binding; a cron keeps it warm

Frontend

  • Plain HTML, CSS and JavaScript, no framework
  • Our own WebGL shader for the hero
  • Canvas halftone archive
  • Self-hosted fonts

Evaluation

  • Offline scorer: pack answerability, citation F1, cost
  • 526 dev questions and a 200-session test-scale split
  • Five rounds of improvements overnight
